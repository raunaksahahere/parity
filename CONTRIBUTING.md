# Contributing

## Setup

```bash
uv sync --extra reference     # reference extra pulls CPU PyTorch; needed for live runs only
uv run pytest                 # no model or server needed: fakes and recorded fixtures
uv run ruff check . && uv run ruff format --check .
uv run mypy
```

Python 3.12, `uv` for the environment, `ruff` for lint and formatting, `mypy --strict` on
`src/parity`. All of `pytest`, `ruff` and `mypy` must pass before a change is merged.

## Ground rules

* **Numbers in docs come from runs.** Never write a measured quantity by hand. Validation
  tables are generated by `parity inject-faults summarize` from `results.jsonl`.
* **Statistics get a simulation test.** A new test or estimator needs a test on simulated data:
  calibration (false-positive rate near nominal) and power against a known alternative.
* **Verdicts need evidence.** A probe that cannot test says SKIPPED or INCONCLUSIVE, never PASS.
* **Pin and record.** Anything that changes results (suite data, thresholds, defaults) bumps a
  version and is recorded in `docs/decisions.md`. Changes to the report schema must update
  `docs/report-schema.json` (a test guards it) and bump `SCHEMA_VERSION` if incompatible.
* **No secrets in output.** Keys are read from environment variables only and never stored.
* Keep scope tight. A leaderboard and MoE/vision support are out of scope for v0.1.

## Adding things

* A probe: see [docs/adding-probes.md](docs/adding-probes.md).
* A provider adapter: subclass `Adapter` in `src/parity/adapters/`, normalize into
  `PositionLogprobs`, add recorded fixtures under `tests/fixtures/`. Say plainly in the module
  docstring whether it was validated against a live server.
* A fault scenario: add it to `src/parity/faults/scenarios.py`; if it simulates a server bug,
  implement it as a request mutation in `faults/proxy.py`.

## Commits

Small and frequent, imperative subject lines ("Add sampler G-test"). Run the full checks first.
